# AGENTS.md — правила работы над Slate

Этот файл читается в начале каждой сессии. Он важнее привычек и шаблонов.

## Что это за проект

Slate — совместная доска: рисование, текст, фигуры, стикеры, изображения.
Клиент — JavaFX 17 / Java 17, сервер — Java 21 + WebSocket + MongoDB.
Целевая картина — три сценария из одного клиента: «только я» (локально, без
сервера), «в моей сети» (встроенный хост) и «свой сервер в интернете».
Подробности и фазы — в `docs/PROGRESS.md` и `docs/DECISIONS.md`.

## Правила

1. **Сначала читай, потом меняй.** Описания и README могут расходиться с кодом.
   Источник истины — код. Расхождения фиксируй в `docs/AUDIT.md`.
2. **Работай фазами.** Не начинай следующую фазу, пока не выполнены критерии
   приёмки текущей. После фазы обновляй `docs/PROGRESS.md`.
3. **Маленькие шаги.** Один логический коммит — одно изменение, Conventional
   Commits. После каждого коммита сборка и тесты должны быть зелёными.
4. **Проверяй, а не «кажется, работает».** Для UI — запусти клиент и сделай
   скриншот. Для протокола — интеграционный тест с двумя клиентами. Если
   проверить нечем, скажи об этом прямо.
5. **Совместимость данных.** Не теряй существующие доски и ключи устройств.
   Изменения формата — только с миграцией и тестом на ней.
6. **Не раздувай.** Сначала «Критично» и «Важно». Неочевидный выбор фиксируй в
   `docs/DECISIONS.md`; спрашивай только про необратимое (лицензия, формат
   файла, удаление функций).
7. **Строки интерфейса — через ресурсы локализации** (`ru`, `en`). Новый текст
   не добавляй в код. Существующие строки выносятся по мере правок.
8. **Безопасность по умолчанию.** Всё сетевое по умолчанию слушает loopback;
   наружу — только явным действием пользователя.

## Сборка и проверка

Системная Java может быть 11 — **всегда задавай JAVA_HOME**.

```bash
# клиент: компиляция + unit-тесты
JAVA_HOME=/usr/lib/jvm/openjdk17 ./mvnw -B clean verify

# сервер: unit-тесты (интеграционные пропускаются)
JAVA_HOME=/usr/lib/jvm/openjdk21 ./mvnw -B -f java-collab/server/pom.xml clean verify

# сервер: unit + интеграционные тесты с настоящей MongoDB
SLATE_INTEGRATION_TESTS=1 MONGO_DB=canvas_collab_test \
MONGO_URI=mongodb://localhost:27017 \
JAVA_HOME=/usr/lib/jvm/openjdk21 \
./mvnw -B -f java-collab/server/pom.xml verify

# запуск
./run-server.sh
./run-client.sh
```

Интеграционные тесты **разрушительны** для базы: они требуют, чтобы `MONGO_DB`
содержал `test`, и очищают её. Никогда не запускай их с рабочей базой.

CI: `.github/workflows/ci.yml` — клиент на Linux/Windows/macOS (JDK 17),
сервер с MongoDB на Linux (JDK 21).

## Структура

```
src/main/java/org/example/canvasproject/   клиент: элементы, команды, UI
src/main/resources/                        FXML, CSS, иконки
src/test/java/                             unit- и страховочные тесты клиента
java-collab/server/                        отдельный Maven-проект сервера
docs/                                      аудит, решения, прогресс, протокол
```

## Соглашения по коду

- Java 17 для клиента, Java 21 для сервера; пакеты — строчные.
- UI-поток неприкосновенен: сеть и диск — вне его, обновления сцены — через
  `Platform.runLater`.
- Новые типы элементов и сообщений протокола: сначала запись в
  `docs/PROTOCOL.md`, затем реализация и тест.
- Не добавляй зависимости без необходимости; объясняй выбор в `DECISIONS.md`.
- Секреты, ключи устройств и коды приглашений не попадают в логи, скриншоты и
  тестовые артефакты.
- Комментарии — по делу; существующие русские комментарии не переводить.

## Перед коммитом

- `git status` не должен содержать `target/`, `.env`, локальные конфиги.
- Тесты, относящиеся к изменению, зелёные; полный прогон — перед релизом.
- В сообщении коммита: что и зачем, а не «fix».
